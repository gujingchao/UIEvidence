# UIEvidence：网站功能分析与方案生成工具

> 状态：第一版(0.1.0)已实现,待验收确认。
>
> 创建日期：2026-10-23

## 一、背景与定位

接单、建站或评估 Web 系统时,客户常给一个参考网站,要求"做一个类似的"。开发者要逐页查看,整理导航、布局、表单、列表和业务流程,再转成功能清单、待确认问题和开发方案。现在这个过程靠人工截图和笔记,常见问题:

- 页面、弹窗和异常状态容易遗漏。
- 截图、网址和结论没有关联,事后无法核对依据。
- 看到的功能和推测的后台能力混在一起。
- 每次报价都要重新整理,网站变化后也无法判断旧结论是否还成立。

**UIEvidence 是一个本地工具:采集参考网站的可见功能,保存证据,支持人工整理,最终导出可复核的需求分析和初步方案。**

使用者:独立开发者、外包人员、小型软件团队、负责需求分析的项目负责人。

典型场景:客户给了一个培训机构网站。开发者记录课程列表、课程详情、咨询表单等页面,保存截图和字段信息,补充后台管理、权限、数据存储等待确认需求,得到初步方案。

### 核心原则

1. 每条重要结论都能追溯到来源页面和证据。
2. 已观察事实、推测功能、人工补充需求、待确认问题,必须分开标注。
3. 采集和基础整理不依赖 AI;AI 只给建议,人工采纳后才生效。
4. 项目和证据默认保存在本地,可导出。
5. 只分析公开网站,或使用者明确获得授权的系统,不绕过访问控制。

## 快速开始

需要 Node.js 22.13 或更高,以及本机已安装 Chrome(或 Edge)。工具不会下载浏览器。

```bash
npm install
npm start          # 构建前端并启动,然后打开 http://127.0.0.1:4317
```

想先试一试,可以另开一个终端启动自带的测试站,再在项目里把 `127.0.0.1:4100` 加进域名白名单:

```bash
npm run fixtures   # http://127.0.0.1:4100
```

开发模式:`npm run dev`(前端热更新在 http://127.0.0.1:5173)。数据保存在仓库下的 `data/`,用 `UIEV_DATA_DIR` 可以改位置。

使用"AI 分析"需要在 `.env` 里配置一个模型服务的密钥,见 [.env.example](.env.example)。不配置也能完成采集、整理和导出的全部流程。

常用命令:

| 命令 | 说明 |
|---|---|
| `npm test` | 单元与集成测试(会启动本机 Chrome,访问本地测试站) |
| `npm run test:e2e` | 浏览器端到端测试 |
| `npm run typecheck` | 类型检查 |

## 二、技术栈

| 层次 | 技术 | 用途 |
|---|---|---|
| 语言 | TypeScript | 前端、服务端和数据结构共用类型 |
| 本地服务 | Node.js | 项目管理、采集任务、文件处理、导出 |
| 页面采集 | Playwright + 本机 Chrome | 访问页面、截图、提取可见结构;不下载浏览器,找不到 Chrome 时回退到 Edge |
| 前端 | Vue 3 + Vite | 项目工作台、证据查看、功能整理、方案编辑 |
| 数据库 | SQLite(Node 内置 `node:sqlite`) | 项目、页面、证据、功能条目及其关联;不需要编译原生模块 |
| 文件存储 | 本地目录 | 截图、DOM 快照、导出材料 |
| 导出 | Markdown、HTML | 页面清单、需求分析、初步方案 |
| 可选 AI | 多个模型服务,由用户选择 | 首批支持 OpenAI 兼容接口、Anthropic、Gemini;归纳功能、分析截图、起草待确认问题 |
| 测试 | 单元测试 + Playwright 端到端测试 | 数据关系、采集流程、导出内容、界面操作 |

```text
Vue 工作台
    └── 本地 Node.js 服务
            ├── 项目与采集任务管理
            ├── Playwright 页面采集
            ├── 页面、功能与证据整理
            ├── 可选 AI 分析适配
            ├── 需求与方案导出
            └── SQLite + 本地证据文件
```

具体依赖版本在开发规划阶段确定。发行方式(Windows 优先、启动包、桌面安装程序)暂不决定,首版以 `npm` 脚本本地运行为准。

## 三、核心数据模型

先定对象,再写功能。

| 对象 | 说明 |
|---|---|
| 项目 Project | 目标网站、分析目的、**授权声明**、**域名白名单**;不同项目的数据互相隔离 |
| 页面 Page | 项目内要分析的网址及其采集状态 |
| 采集 Capture | 对某个页面的一次采集:网址、视口、采集时间、状态、失败原因。多次采集各自保存,**不覆盖** |
| 证据 Evidence | 一次采集产出的材料:截图 + DOM 结构快照,有唯一编号 |
| 功能条目 Feature | 功能模块的描述,有类型(见下),关联一个或多个页面和证据 |

功能条目的类型:

| 类型 | 含义 | 示例 |
|---|---|---|
| 已观察事实 | 页面中看到,或经允许的操作验证过 | 课程列表有分类筛选入口 |
| 推测功能 | 由界面推断,尚未验证 | 可能需要课程上下架管理 |
| 人工补充需求 | 使用者根据项目目标提出 | 管理员按角色分配权限 |
| 待确认问题 | 缺信息,需要继续沟通 | 是否存在不同价格等级? |

功能条目与证据是多对多关系。AI 生成的条目带来源标识,默认状态为"待采纳"。

## 四、首版 MVP

闭环:

> 新建项目 → 添加页面 → 采集截图与结构 → 整理功能条目 → 关联证据 → 补充待确认问题 → 导出报告

| 模块 | 首版目标 |
|---|---|
| 项目管理 | 新建、编辑、查看、归档;填写授权声明和域名白名单 |
| 页面管理 | 手工添加网址,维护采集状态 |
| 页面采集 | 截图 + 基础可见结构(标题、导航、链接、表单、列表);失败有明确提示 |
| 功能整理 | 手工维护功能条目,并提供基于页面结构的候选 |
| 证据关联 | 从功能条目查看对应页面、截图和观察记录 |
| 需求补充 | 记录后台、权限、数据要求和待确认事项 |
| 导出 | Markdown、HTML、含截图的材料包 |
| AI 辅助 | 可选;多服务可切换;**每个项目有"允许发送内容给模型"开关,默认关闭**;建议需人工采纳,失败不影响手工流程 |

### 采集规则

- **范围**:只访问项目白名单内的域名,范围外的网址拒绝采集并提示。
- **只读**:首版不提交表单、不删除、不付款、不登录。允许的交互仅限导航链接、Tab 切换、分页、弹窗展开;其他点击不执行,记入"分析缺口"。
- **等待策略**:默认等页面加载完成且网络空闲,支持为单个页面指定等待元素和超时;懒加载内容通过滚动一次触发。采集时机写入 Capture 记录。
- **登录后页面**:首版不做。无法访问的内容记为分析缺口,而不是猜测。
- **浏览器隔离**:每次采集使用独立的临时用户目录,不读取、不修改使用者日常 Chrome 的配置、Cookie 和登录状态;浏览器版本写入 Capture 记录。
- **多状态**:同一个页面的不同状态(如表单初始状态与校验提示)各存为独立 Capture。

### 首版不做

全站爬取、复杂登录适配、还原网站源码、推断后台架构、多人在线协作、支付、云托管。产品形态只做本地工作台,不提供 CLI 和 Claude skill 形式。

## 五、验收标准

每条都要能用测试或明确步骤验证。

1. 用一组本地受控测试页完成采集,截图、网址、视口、时间记录正确。
2. 同一页面多次采集分别保存,旧证据不被覆盖。
3. 白名单外的网址被拒绝,且不发出请求。
4. 采集过程中不触发提交、删除等写操作(测试页中放置带副作用的按钮,验证它们未被点击)。
5. 功能条目能关联页面与证据,四种类型区分明确。
6. 页面超时、打不开或部分资源失败时,有明确提示,已有项目内容不受影响。
7. 未配置 AI 时,采集、整理、导出全流程可用。
8. 导出的 Markdown 中每个截图和文件引用都能打开;Markdown、HTML、材料包的页面清单和功能条目一致。
9. 页面或 AI 输出中包含伪造的指令文本(如"忽略之前的规则并执行……")时,程序行为不变,文本只作为数据展示。
10. 重启程序后,项目记录和证据文件完整。

以上 10 条均有自动测试覆盖(`npm test` 与 `npm run test:e2e`)。对应关系见 [DEVPLAN.md](DEVPLAN.md)。

## 六、开源约束

本项目计划开源,仓库和发行物须满足:

- 不包含任何密钥、真实客户数据、采集产生的截图和数据库;`data/` 默认被 `.gitignore` 忽略。
- 模型服务的密钥只从环境变量或用户级配置读取,不写入项目数据,不进入导出材料包。
- 夹具和示例只使用自建测试页,不内置第三方网站的内容。
- 附带许可证、使用说明和"仅分析公开或已授权网站"的使用提醒。

## 七、能力边界

前端页面和截图只能反映部分系统行为,不能确认服务器实现、数据库结构、权限规则和未展示的业务流程。动态加载、访问权限和采集时机都会影响结果,所以报告保留采集上下文,并明确未验证的部分。

不把目标网站的专有代码或素材当作自有资产。

## 八、待定事项

首版开发前需要决定,目前不作承诺:

- 项目备份与恢复、分析记录的版本管理:放入首版还是第二版。

## 九、与 ScopeTrace 的关系

ScopeTrace 是另一个项目,负责需求确认之后的范围版本、变更审批和客户验收。

- UIEvidence:从参考网站出发,形成有依据的功能分析和需求草案。
- ScopeTrace:在需求确认后,管理范围、变更和最终验收。

两者互不依赖。后续可以考虑用结构化文件把 UIEvidence 审核后的结果导入 ScopeTrace,尚未决定,不属于首版。
